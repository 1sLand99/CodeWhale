# v0.9.2 terminal / key / modal acceptance matrix (#3758)

Status vocabulary, used literally:

- **PASS** — an automated cell exists, and this document names the test that
  covers it. It does **not** claim the test was run in this session; see
  "How to run" below.
- **UNRUN** — no automated coverage. Every `UNRUN` row is a literal physical
  observation in a real terminal emulator or over a real SSH link, which a
  pseudo-terminal reproduces the byte protocol of but not the emulator.

Nothing in this document asserts a test result. It records which cells have
automated acceptance and which remain human work.

## What is automated, and where

| Test target | File |
| --- | --- |
| Provider-free terminal/key/modal matrix | `crates/tui/tests/terminal_matrix_qa.rs` |
| Running-turn contract against a loopback mock provider | `crates/tui/tests/release_runtime_qa.rs` |
| Shortcut-copy canonical-action audit | `crates/tui/src/tui/keybindings.rs` (unit tests) |
| PTY harness, terminal-mode ledger, view-stack trace reader | `crates/tui/tests/support/qa_harness/` |

Supporting machinery added for this matrix:

- `support/qa_harness/modes.rs` — replays the raw PTY control stream into a
  DEC-private-mode ledger. Terminal-mode restoration is invisible on the
  rendered frame, so the control stream is the only truthful evidence.
- `support/qa_harness/view_log.rs` — reads the product's existing
  `codewhale_tui::view_stack` trace records (push/pop, `ModalKind`, depth).
  Modal coverage asserts on those records rather than on "the frame changed",
  because a replaced modal and a closed modal render identically.
- `Harness::transcript` / `terminal_modes` / `diagnostics` — every bounded wait
  fails with the frame **and** the mode ledger.

### How to run

```
cargo test -p codewhale-tui --test terminal_matrix_qa --locked -- --test-threads=1
cargo test -p codewhale-tui --test release_runtime_qa --locked -- --test-threads=1
cargo test -p codewhale-tui --bin codewhale-tui --locked keybindings
```

These are Unix-gated (`#![cfg(unix)]`); Windows ConPTY input plumbing is a
separate audit and its rows are `UNRUN` below.

## UNRUN — physical observation only

Every row here needs a human at a real terminal. A PTY delivers the same bytes,
but it is not the emulator: it has no font stack, no GPU renderer, no
Option-key mapping, no window manager, and no network path.

| Cell | Status | Why it cannot be automated here |
| --- | --- | --- |
| iTerm2 — rendering, colors, wide glyphs | UNRUN | Emulator-specific renderer and font shaping |
| iTerm2 — `Cmd+V` paste, `⌥` chords, Cmd-forwarding config | UNRUN | Depends on the emulator's own key remapping |
| macOS Terminal.app — 256-color fallback appearance | UNRUN | The visual result of the tier, not the emitted bytes |
| macOS Terminal.app — Option-as-Meta behaviour | UNRUN | Emulator preference, not a byte protocol |
| WezTerm — kitty keyboard protocol chords (Ctrl+Shift+A/O/T) | UNRUN | Requires the emulator's enhanced-keyboard implementation |
| WezTerm — mouse selection and OSC 52 clipboard | UNRUN | Requires a real clipboard and window system |
| Real SSH session — paste, latency, resize propagation | UNRUN | Needs a real network path and remote tty |
| tmux inside a real emulator — nested capability negotiation | UNRUN | Nested terminal behaviour, not reproducible in a bare PTY |
| Windows Terminal / ConPTY — input plumbing | UNRUN | The PTY suite is `#![cfg(unix)]`; ConPTY needs its own audit |
| System notification banner appearance | UNRUN | macOS attributes it to the unbundled `osascript` host (#4847) |

Physical observations, when they are made, belong in a separate record. Do not
fold a one-off visual observation into the PASS tables above — a flaky or
unrepeatable observation carries different weight than a test that runs on
every change, and merging them would make both less trustworthy.

## Known gaps

- Provider-dependent modals (model/provider/fleet/setup/session/worktree) have
  no automated open/close cell yet.
- The matrix is Unix-only.
- `NO_COLOR` has boot coverage, not behavioural coverage, because it is not
  currently a contract.
